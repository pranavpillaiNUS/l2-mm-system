\section{Verification, Failure Analysis, and Limits}

\subsection{What verification establishes}

The project uses complementary forms of evidence. Synthetic tests isolate
mechanics such as post-only arrival, cancel/fill races, same-millisecond
ordering, gap invalidation, volume conservation, and worst-case exposure.
Artifact tests check identities, workflow completeness, expected paths,
parameter locks, and decision rules. Differential tests check book and
pipeline behavior across implementations. Native tests and sanitizers add
memory and arithmetic checks. None of these alone establishes that aggregate
L2 queue assumptions match a live exchange.

The V3 manifest lists every expected workflow step, its command and durable
outputs, source identity, and raw-input hashes. The verifier derives the
complete expected 61-step workflow and rejects missing steps, redirected
output paths, incomplete artifacts, and mismatched frozen inventory entries.
A self-consistent empty directory is not accepted as a completed study. The
decision summarizer recomputes primary gates from the underlying regression
and bucket results and independently reconstructs clustered contrasts.

Recorded-revision verification resolves the manifest's exact Git commit and
hashes its Python source bytes. It does not accept an arbitrary commit merely
because a subset of files happens to match. Default verification instead
requires the current working source to match the research fingerprint. This
distinction allows later native integration, benchmark corrections, and
verification improvements without rewriting the historical research run's
identity.

Clone-level \code{--artifacts-only} verification checks committed artifacts,
the frozen input inventory, and recorded source identity without claiming to
have read absent raw captures. Full verification additionally hashes the
selected raw files. Both modes state their boundary explicitly. CSV byte
identity is protected against checkout line-ending conversion, because
line-ending changes can invalidate a correct logical table's recorded hash.

The common lesson is to correct the measurement boundary before strengthening
the claim. Some failures require revised implementation tests; others change
the economic estimand and require a new run. A provenance boundary prevents
the first kind of fix from quietly relabeling the second kind of evidence.

\subsection{Empirical and inferential limits}

\begin{itemize}
\item \textbf{Narrow market coverage.} One venue, one spot instrument, and a
short April--May 2026 period cannot establish cross-asset, cross-venue, or
long-run robustness.
\item \textbf{Selected availability.} Only 775 of 1,193 inventoried hours
passed the capture requirements. Operational failures can correlate with
stressed markets, making missingness economically relevant.
\item \textbf{Exploratory anchors.} Six baseline-selection windows remain in
the 24-window panel. The expanded study is development evidence, not a wholly
untouched confirmatory sample.
\item \textbf{Hourly resets.} Residual inventory is marked and discarded
without liquidation cost at each hour boundary. Results are not continuous
portfolio returns or a capacity study.
\item \textbf{Dependence.} Window bootstrap and local HAC errors answer
different uncertainty questions. Nearby windows can share regimes; neither
method creates independent market histories.
\item \textbf{Conditional selection.} The clustered contrast interval fixes
bucket labels selected from the pooled sample and is not selection-adjusted.
The 30-observation floor and 1.0 bps screen are heuristics, not a formal power
design or a universal profitability criterion.
\item \textbf{Holdout status.} Reserved identities and regime descriptors
were examined, but strategy outcomes remain sealed. There is no unseen
candidate result supporting the report's conclusion.
\end{itemize}

\subsection{Execution and operational limits}

Aggregate L2 reveals displayed quantity, not individual order rank, hidden
liquidity, iceberg refresh, or the location of cancelled orders in the queue.
Cancellation credit is uncalibrated. The modeled timestamp axis mixes local
request barriers, depth \code{E}, trade \code{T}, and receipt-order constraints;
the snapshot correction removes an identified early-release exposure without
calibrating client observation or network latency.

The simulator assumes its small orders do not alter the recorded market.
Endogenous market impact, account fee tiers, acknowledgement/fill calibration,
exchange throttles, self-trade prevention, and production gateway behavior are
outside the experiment. Counterfactual taker execution uses a shadow
liquidity ledger only until the next observed depth update and would require
stronger reconciliation for taker-heavy work. No live account calibration is
claimed.

The native input domain is deliberately narrower than arbitrary Python
Decimal. Its binding retains the GIL and performs Decimal conversion at the
boundary, so it does not promise parallel throughput or end-to-end
acceleration. Native parity covers implemented semantics on the tested domain;
it does not validate queue assumptions or the economic hypothesis.

\subsection{Completed outcome and useful extensions}

The completed project supplies a deterministic offline workflow, a corrected
and source-identified development study, a stopped candidate gate, an intact
holdout boundary, a usable native book backend, differential validation, and
separately scoped measurements. The negative conditional result is a research
outcome, rather than unfinished strategy tuning.

Further work has distinct questions: a new signal transform needs a new
development protocol; a current-model credit/latency grid needs a versioned
sensitivity study; live calibration needs observed acknowledgements and
fills; and a full native execution engine needs a broader arithmetic/event
parity contract. Those are extensions of the completed scope, not evidence
already supplied by the present results.
